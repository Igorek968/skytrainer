# Подключение ЮKassa к ТвойТренер.рф

Сейчас в **skiinstruct** оплата идёт через **Stripe** (или mock без ключа в dev).  
В корневом **legacy API** (`api/`) уже есть черновик ЮKassa — для единого продакшена лучше перенести логику в Next.js.

## За 2 дня до подключения — подготовьте

1. **Личный кабинет ЮKassa** — shopId и секретный ключ (тестовый магазин для проверки).
2. **Домен с HTTPS** — webhook и `return_url` только по HTTPS (localhost — только mock/ручная проверка).
3. **Реквизиты в оферте** — `NEXT_PUBLIC_LEGAL_ENTITY_NAME`, ИНН, контакты поддержки.
4. **Сценарий оплаты** (зафиксируйте с юристом):
   - предоплата при создании заказа (`AWAITING_PAYMENT` → `PAID` → очередь инструкторов);
   - комиссия платформы 15% — как отражается в чеке/агентском договоре.

## Переменные окружения (добавить в корневой `.env` и `docker-compose.yml`)

```env
YOOKASSA_SHOP_ID=
YOOKASSA_SECRET_KEY=
# Публичный URL приложения для return_url после оплаты
SKIINSTRUCT_PUBLIC_APP_URL=https://your-domain.ru
```

На проде mock отключён в `skiinstruct/.env.production` и в корневом `.env`:

```env
ALLOW_MOCK_CHECKOUT=0
YOOKASSA_SHOP_ID=...
YOOKASSA_SECRET_KEY=...
```

**Webhook в ЛК ЮKassa:** `https://твойтренер.рф/api/webhooks/yookassa`  
**События:** `payment.succeeded`, `payment_method.active`  
**Чеки:** включить «Чеки от ЮKassa» (receipt передаётся при создании платежа в API).

## Привязка карты (автоплатежи)

ЮKassa включила привязку карт для магазина. В коде это `YOOKASSA_RECURRING_PAYMENTS` (по умолчанию **вкл**, если заданы shopId/ключ; выключить: `=0`).

Что умеет сервис:

1. **Привязка без списания** — «Личные данные» → «Привязать карту» (`POST /v3/payment_methods`).
2. **Привязка вместе с оплатой** — первый заказ: `save_payment_method: true`.
3. **Повторная оплата** — списание по сохранённому `payment_method_id` (урок и событие), без ввода карты. Если банк требует 3‑D Secure — редирект на форму ЮKassa.
4. **Отвязка** — в кабинете удаляем токен у себя (ЮKassa не удаляет способ оплаты на своей стороне).

В оферте: п. 5.4.1 (согласие, нет абонентки по расписанию, как отключить).

В ЛК ЮKassa добавьте webhook-событие **`payment_method.active`**, если его ещё нет.

## Точки интеграции в коде

| Шаг | Файл / действие |
|-----|------------------|
| 1 | `POST /api/payments/yookassa/create` — создание платежа ЮKassa (чек + return_url) |
| 2 | `POST /api/webhooks/yookassa` — `payment.succeeded`, `Order.paymentStatus`, `assignInstructorByQueue` |
| 3 | UI: `client-order-checkout-dialog.tsx`, `client/orders/[id]/page.tsx` — `redirectToOrderCheckout()` |
| 4 | Prisma: `yookassaPaymentId` на `Order` и `Payment` |
| 5 | Редиректы success/cancel: `/client/orders/[id]?paid=1` |

Референс в репозитории: `api/src/services/yookassa.ts`, `api/src/routes/payment.ts`.

## Возвраты и события

- Возвраты при отмене/истечении заявки — `POST /v3/refunds` через `order-refund.ts`
- Оплата событий — тот же webhook, metadata `type: "event"`
- На проде: `YOOKASSA_WEBHOOK_VERIFY_IP=1` (опционально)

## Проверка после подключения

- [ ] Тестовый платёж 1 ₽ в тестовом магазине ЮKassa
- [ ] Webhook доходит на прод (логи, статус заказа `PAID`)
- [ ] После оплаты инструктор получает заявку в очереди
- [ ] Отмена заказа → `refundStatus: COMPLETED` в админке
- [ ] Заявка на выплату инструктора → админ `/admin/finance`

## Пока ЮKassa не подключена (локально)

- Пустой `STRIPE_SECRET_KEY` + `ALLOW_MOCK_CHECKOUT=1` (или dev по умолчанию) — mock-оплата без карты.
- Для демо инвестору этого достаточно; для приёма денег в РФ нужна ЮKassa (или Stripe, если доступен).

## Тестовый прогон на VPS (без реальной ЮKassa)

В корневом `.env` на сервере:

```env
ALLOW_MOCK_CHECKOUT=1
```

Перезапуск: `docker compose up -d --build` (или ваш скрипт деплоя).

Оплата идёт без ЮKassa: карта «4242» привязывается автоматически, заказ сразу `PAID` → инструктору уходит заявка.

**После теста обязательно:** `ALLOW_MOCK_CHECKOUT=0` и перезапуск.

### Сценарий прогона

1. **Инструктор:** кабинет → «Соответствие» (документы одобрены админом) → статус **«На линии»**.
2. **Клиент:** карта / поиск → выбор инструктора → оформление → «Оплатить» (mock, без редиректа в банк).
3. **Клиент:** `/client/orders/[id]` — статус не «Ожидает оплаты», а «Ожидает ответа инструктора» или «Принято».
4. **Инструктор:** всплывающее окно + звук (клик по странице до заявки) + письмо на email.
5. **Срочная заявка:** инструктор должен быть **на линии в момент оплаты**.
